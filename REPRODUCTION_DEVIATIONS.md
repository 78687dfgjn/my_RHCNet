# Reproduction Deviations

This run follows the checked-in RHCNet implementation and records what differs from the paper. The paper's explicit training schedule is restored in separate configs. No original model source file has been changed.

| Area | Paper | Repository / data actually used | Effect and handling |
|---|---|---|---|
| Head and assigner | Figure 2 describes a dual-task head with AutoAssign. | The README-indicated config selects TOOD/TOODHead, anchor-based, with ATSS for four epochs followed by TaskAlignedAssigner. | Material architecture difference; retained and reported rather than silently claiming AutoAssign. |
| LAM / RGFE | Both are described in the paper backbone. | LAM helper is not instantiated by the configured ResNet; no RGFE class/call exists. | Missing from actual forward; source was not rewritten. The resulting run cannot establish a complete paper-equivalent backbone. |
| HFCP / CGCA / PAM | HFCP contains the described calibration/feature paths. | HFCP, CGCA, and PAM execute; Focus instances are constructed but bypassed. CGCA performs CPU sklearn KMeans over channel feature maps after `.cpu().numpy()`. At smoke iteration 800, the first fifteen 50-iteration windows averaged 5.11 s/iter; the latest seven averaged 7.05 s/iter. | The actual implemented path is retained; low sampled GPU use and high main-process CPU use are consistent with CGCA synchronization/KMeans as a throughput bottleneck (not a controlled ablation). A separate CUDA KMeans variant is a possible optimization to evaluate, but it has not replaced the original path or been claimed as an official reproduction. It also differs from pixel-feature clustering in the paper. |
| Loss / assignment quality | Paper describes an IoU and centerness quality target. | The selected TOOD head uses FocalLoss initially, then QualityFocalLoss with its task alignment metric; GIoU weight is 2. | The source loss/assigner behavior is retained and documented. |
| LR milestones | Epochs 27 and 32. | Base schedule uses 24 and 30. | Reproduction configs set `[27, 32]`; warmup (500 iterations, ratio 0.001) is sourced from the repository because the paper does not specify it. |
| DUO validation and empty images | Paper reports a DUO test result. | Supplied archive has 6,671 train and 1,111 test images, with no separate validation split. MMDetection's configured default filters 54 train and 11 test images that contain no annotations; 6,617 train / 1,100 test images are used. | Test evaluation is reserved for the one-time smoke-path check and final result; it is not used to select a best checkpoint. Empty-image filtering is recorded rather than overridden. |
| UTDAC annotations and overlap | Paper table reports 5,643 images. | Supplied standard four-class files have 5,168 train and 1,293 validation entries (6,461 total). `train2017/000004.jpg` and `val2017/000001.jpg` have identical bytes; five boxes have negative dimensions. | The derived annotations keep the validation copy, leaving 5,167 train / 1,293 validation images; remove annotations for the duplicate train image and the five invalid boxes. Derived annotation counts are 37,186 / 9,488. Source JSON is preserved. The split/count difference can change results. |
| UTDAC test splits | Paper reports a UTDAC result. | Archive includes `testA.json`/`testB.json` but not their image directories. | Use the available standard validation split; do not claim an unavailable test-set evaluation. |
| Hardware | Paper results were produced under the paper's experimental setup. | One RTX 2080 Ti (22,528 MiB). | Single-GPU results and runtime are reported directly; no equivalence to an undocumented multi-GPU setup is assumed. |

The full code-path evidence and dataset file counts are in `reproduction_logs/code_audit.md` and `reproduction_logs/dataset_audit.md`.
