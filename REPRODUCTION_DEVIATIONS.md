# Reproduction Deviations

This task is defined as **RHCNet Official Released-Code Reproduction**, not exact paper-architecture reproduction. The selected baseline configs inherit the author's released implementation and `[24, 30]` LR schedule. Separate `*_paper_hparam.py` files record the paper's explicit `[27, 32]` schedule without changing the released architecture. No original model source file has been changed.

| Area | Paper | Repository / data actually used | Effect and handling |
|---|---|---|---|
| Head and assigner | Figure 2 describes a dual-task head with AutoAssign. | The README-indicated config selects TOOD/TOODHead, anchor-based, with ATSS for four epochs followed by TaskAlignedAssigner. | Material architecture difference; retained and reported rather than silently claiming AutoAssign. |
| LAM / RGFE | Both are described in the paper backbone. | LAM helper is not instantiated by the configured ResNet; no RGFE class/call exists. | Missing from actual forward; source was not rewritten. The resulting run cannot establish a complete paper-equivalent backbone. |
| HFCP / CGCA / PAM | HFCP contains the described calibration/feature paths. | HFCP, CGCA, and PAM execute; Focus instances are constructed but bypassed. CGCA performs CPU sklearn KMeans over channel feature maps after `.cpu().numpy()`. Smoke reached iter 1,550; mean/median over logged 50-iteration windows so far are 4.52/3.51 s/iter. | The actual implemented path is retained; sampled GPU use has been low and the main process CPU use high, consistent with CGCA synchronization/KMeans as a throughput bottleneck (not a controlled ablation). A separate CUDA KMeans variant is only a possible future optimization; it has not replaced the original path or been claimed as an official reproduction. It also differs from pixel-feature clustering in the paper. |
| Loss / assignment quality | Paper describes an IoU and centerness quality target. | The selected TOOD head uses FocalLoss initially, then QualityFocalLoss with its task alignment metric; GIoU weight is 2. | The source loss/assigner behavior is retained and documented. |
| LR milestones | Paper-hparam reference: epochs 27 and 32. | Selected official-release baseline inherits `[24, 30]` from `configs/_base_/schedules/schedule_2x.py`. | `*_official_release.py` keeps the released schedule; `*_paper_hparam.py` uses `[27, 32]`. Warmup (500 iterations, ratio 0.001) is sourced from repository code because the paper does not specify it. |
| DUO validation and empty images | Paper reports a DUO test result. | Supplied archive has 6,671 train and 1,111 test images, with no separate validation split. MMDetection's configured default filters 54 train and 11 test images that contain no annotations; 6,617 train / 1,100 test images are used. | Test evaluation is reserved for the one-time smoke-path check and final result; it is not used to select a best checkpoint. Empty-image filtering is recorded rather than overridden. |
| UTDAC protocol and overlap | Paper states 5,643 images. | Selected protocol is standard public UTDAC2020: 5,168 train + 1,293 val = 6,461 entries; 6,460 unique image contents. One identical-content image pair crosses splits; five raw boxes have negative dimensions. | Original image entries and JSONs are used unchanged. The duplicate and malformed boxes are recorded, not manually removed. The unchanged MMDetection parser skips the five invalid boxes when making training targets (parsed 37,192 train / 9,488 val); image counts remain full. Results will be labeled `standard public UTDAC2020 protocol`, not equated with the paper's 5,643-image protocol. A prior derived-clean JSON folder remains unselected and is not referenced by either config. |
| UTDAC test splits | Paper reports a UTDAC result. | Archive includes `testA.json`/`testB.json` but not their image directories. | Use the available standard validation split; do not claim an unavailable test-set evaluation. |
| Hardware | Paper results were produced under the paper's experimental setup. | One RTX 2080 Ti (22,528 MiB). | Single-GPU results and runtime are reported directly; no equivalence to an undocumented multi-GPU setup is assumed. |

The full code-path evidence and dataset file counts are in `reproduction_logs/code_audit.md` and `reproduction_logs/dataset_audit.md`. The current smoke is not a 35-epoch run; full training is paused until its gate report is presented and the user explicitly instructs whether to proceed.
